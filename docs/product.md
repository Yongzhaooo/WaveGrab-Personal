# WaveGrab Personal 产品规格

Last confirmed: not yet confirmed

本文描述产品的目标行为，不代表功能均已实现。依据用户在本项目对话中确认的录音场景、说话人区分与名称映射要求，以及 [README](../README.md)。未确认的产品选择标为 `(proposed)`。

## Purpose

为个人在 Windows 上保留可转录的会议录音，支持单麦克风收录多人发言，以及现场人员与远端人员混合参会。录后得到带时间戳、说话人标记的文字，允许用户统一命名，再交给 Codex、agy 或其他工具清洗。

## Expectations

### 主要会议场景

- 情景 1：大家主要轮流说话，声音清楚。即使只有一支麦克风，也能按不同说话人标记发言；不要求每人一条独立音轨。
- 情景 3：现场人员与远端人员共同参会，远端声音通常通过会议室音响或在线会议的 speaker 播放，用户的电脑也加入会议。不同远端人员仍是不同说话人，不因共用扬声器而统一标成一个人。
- 支持按真实音频路径选择录制方式：会议室音响的声音由现场麦克风收录；由本机播放的远端声音可通过系统回环采集，并与麦克风音轨一同保留。电脑加入会议本身不代表它正在输出远端声音。
- 多人同时说话是次要情况。不能可靠判断的片段保留时间位置并标为重叠或未知，不强行归给某个人 `(proposed)`。

### 录音与会议音频独立

- 默认自动识别场景：没有可确认的 Teams 会议，或 Teams 没有向所选虚拟声卡输出时，使用会议室模式，只读所选麦克风。确认单个通话窗口及 VB-CABLE 输出会话时，使用虚拟声卡接收端和实际麦克风双路录制。
- 自动识别在后台进行，准备状态有小点反馈；识别超时或失败时回退为会议室录音，不无限等待。准备期间再按 Alt+R 取消，迟到的检测结果不得启动录音。自动识别不改变 Teams、系统音量或音频路由。
- 用户可关闭自动识别，手动选择会议室或双路录制。双路模式保留合成音频和所选来源的独立音轨。
- Teams 内的静音或 No audio 不被录音程序修改。程序不自动启用被 Windows 禁用的设备，不自动解除硬件或系统静音。
- 无外放录制远端会议时，用户将 Teams 扬声器设为虚拟线路并允许输出，Teams 麦克风继续静音。录音程序同时读取虚拟线路接收端和实际麦克风，不监听或播放采集的声音；物理输出保持静音。此方式不要求 Teams 扬声器也处于静音或 No audio 状态。
- VB-CABLE 由用户单独安装；系统声音列表提供 `CABLE Output` 接收端。双路录制不能将系统声音与麦克风选为同一设备。
- 用户点击「开始录音」或「检查输入」才开始采集。「检查输入」显示输入音量，不通过扬声器回放。
- 设备未收到采样或麦克风采样持续为零时，提示具体来源及可能的静音问题。已录到的其他音轨保留；不把缺失的声音标为完整录制成功。
- 暂停期间不保存声音。静音来源不拖慢其他音轨；保存后的时长与实际有效录制时长相符。
- 录音和处理拥有独立生命周期：停止录音不等待截图组件退出、回看页生成或转录。上一场处理缓慢或失败不阻止新录音；可以一边录制新会议，一边转录已保存的旧会议。正在写入的同一场音频不得开始转录。

### 说话人分段与转录

- 程序提供“录音”“录音记录”“转录与说话人”三个页签；转录由独立本地进程执行，名称编辑与结果查看在程序内完成。
- 转录页以发言列表和正文为主体。已有结果默认收起完整路径、音频/人数设置与说话人改名；没有结果时展开转录设置。正文自动显示选中发言，列表与全文的高度可拖动调整；处理中取消入口保持可见。
- 以单次会议为范围，输出带开始/结束时间、稳定说话人 ID 和正文的发言片段。默认显示为 `Speaker 1`、`Speaker 2` 等，不需要识别真实姓名。
- 同一人轮流发言后再次开口时，继续使用同一说话人 ID；现场人与扬声器里的远端人均参与分段。
- 人数默认依据整场声纹估计；不把用户对某次会议的粗略人数上限写死为全局人数。短促、含糊或不可靠的声纹保留为未知，不为每个异常片段生成新人标签。标签数量是估计，不能当作已核实的参会人数。
- 音轨来源与说话人身份分开：一条 mic 音轨可含多人，一条 system 音轨也可含多个远端人。来源不能直接替代说话人标记。
- 原始转录保留语言、术语、时间戳和不确定内容；清洗稿保留事实、数字、否定和条件，不凭空补充姓名或结论。
- 录后批量处理是默认方式，不要求录制中实时显示转录。
- 双路录音中，同一句远端发言可能既出现在系统回环，又被麦克风从音响收回。后处理避免把它输出为两次发言；具体效果由混合会议样本验证 `(proposed)`。

### 录音记录与文字场景

- 录音记录按开始日期倒序展示日期、时长、场景、状态和备注，可直接进入某次录音的文字页面。已录条目自动出现，不要求逐个选择文件夹。
- 每条录音可保存最多 2000 字的简单备注，以及“会议”或“Desk”文字场景。设置独立于录音设备模式，不改原音频和会话元数据。
- 会议场景保留全部发言，包括低音量、短发言、未知与重叠，不只保留主要两人。
- Desk 仍先区分所有声纹，再按发言时长与响度建议两个主要声纹；用户可改选正文保留的人。不把全部声音强制归为两人。
- Desk 正文排除未选中的已知声纹，另存完整稿和背景候选/待核对稿。未知或重叠可能含主要对话，仍保留正文；界面可显示全部。改名与校正同步影响导出。
- 短录音采用适合少量声纹样本的分组。自动建议需人工核对，不把响度当作可靠的距离或身份。
- 无可用语音时在列表和文字页明确提示；文件保存完整不代表录到了语音。
- 录音记录页直接提供“音频位置”“总结位置”，在资源管理器中选中文件，不自动播放。显示整理状态，并允许已转录的条目生成总结或失败重试。

### 当前会议内统一命名

- 用户可以不命名，直接使用 `Speaker 1` 等标签。
- 用户给某个说话人设置一次显示名，该会议所有对应发言、清洗稿和本地衍生导出统一更新，不需要逐段替换。
- 改名只改变显示名，不改变发言归属、时间戳或原始音频。原始识别输出保留稳定 ID，显示名通过会议内映射关联。
- 名称映射随会议结果保存，重新打开同一会议仍可使用。`Speaker 1` 在另一场会议中是独立标签，不自动沿用前一场会议的姓名。

### 录音文件与通用交接

- 提供 `WaveGrab-Agent.cmd` 本地 JSON 命令行入口：列出录音、查看文件路径、读取按场景筛选的转录、调用现有 AGY 整理，或导入外部 agent 自行生成的笔记。写入复用会话锁与现有导出规则；已有总结须显式选择替换。接口见 [agent-api.md](agent-api.md)。

- 每次录音使用单独文件夹，默认位置是用户的 `Music/WaveGrab`，可在界面修改。
- 保留 `mixed.flac`、所选来源对应的 `mic.flac` / `system.flac`、`HANDOFF.md` 和 `session.json`。会议室模式不生成系统音轨；其 `mic.flac` 与合成音频均代表本次麦克风录音。
- `session.json` 记录设备、文件清单、时长、完成状态和错误；部分失败仍保留可用音频及状态说明。
- 「打开录音文件夹」和「复制交接说明」提供通用入口，不绑定某个 AI 工具。交接包含可用音轨、转录清洗要求及已有的说话人结果和名称映射。
- 转录完成后自动调用本机已登录的 AGY CLI 无头模式，使用 transcript-processing 的 notes 模式整理内部讨论笔记，humanizer 仅用于最后的行文润色；输出一份中文总结，保留英文技术术语。按主题组织讨论、理由与结论，待办、责任人和期限仅在原文明确时列出；不逐段列时间戳与校对内容。长会议分批整理后合并成一份总结。
- 使用 Ka-zar / 共享工程知识库核对术语；只向 AGY 发送所选文字及相关检索证据，不发送音频。知识库不能补写录音缺失的内容；无文字时跳过整理。重大不确定性留在正文，其他校正依据另存核对说明。
- 总结作为独立后台进程生成，不阻塞录音，关闭界面后继续。原音频、原始转录与人工校正保留；总结采用人工校正后的文字，独立保存。失败显示状态并允许重试，不伪报成功。通用交接入口仍可用。

### 会议画面、标记与托盘

- 自动模式确认 Teams 会议正在使用所选虚拟声卡时，自动选择会议窗口；截图默认开启，也可关闭。依据通话控件确认会议，不仅依赖窗口标题；聊天主窗口和入会预览不作为自动截图目标。手动模式可从已确认的会议窗口中选择。
- 约 3 秒一张，只保存选定的会议窗口，不包含窗口外桌面或其他应用，也不自动改抓其他窗口。窗口内显示的共享内容及参会者均在截图范围内。没有有效截图目标时仍可录音。
- 截图压缩保存，最长边不超过 1280 像素，高度不超过 720 像素；完全重复画面不另存。窗口被遮挡时仍可采集；最小化、隐藏或关闭时停止新截图，音频继续。录音暂停期间不截图。
- Alt+R 全局开始／停止录音，Alt+M 在当前录音时间打标。标记和截图时间均扣除暂停时长，录音结束后随会话保存。
- 主窗口隐藏时，主屏右下角、任务栏上方的小点提供反馈：录音时红色常亮，暂停时琥珀色空心，标记成功时短暂变成绿色空心，保存完成后短暂绿色并消失。未录音时按 Alt+M 只闪琥珀色，不制造成功标记。小点不抢焦点、不拦截点击、不发声音。
- 本地回看页提供音频控制、画面时间轴和可点击标记；跳到标记时显示相应画面，不自动播放声音。缺失画面保留缺失状态，不伪称旧图是新画面。
- 默认隐藏主窗口并驻留托盘；托盘可打开设置、开始／停止、打标、回看最近录音及退出。关闭主窗口不会结束录音；退出才保存并释放资源。快捷键被占用时提示，托盘菜单仍可用。
- 开始、停止、打标与异常均不弹消息通知或抢焦点；提示留在应用内及托盘悬停文字中。托盘图标用小色点表示录音、暂停或需处理状态。截图关闭明显的窗口捕获边框，不改 Teams 自身的共享状态标记。

### 分发与使用

- 支持 Windows 源码启动及本地便携程序。用户运行 `dist/WaveGrab-Personal.exe` 或 `Start-WaveGrab.cmd`；移动便携程序时同时保留 `_internal`。
- 用户本地设备选择和录音路径保存在本机配置中；录音与配置不作为公开源码发布内容。

## Non-goals

- 自动识别真实姓名、跨会议声纹人物库或跨会议自动关联身份。
- 为每位参会者配置独立麦克风，或要求用户为普通轮流发言先注册声纹。
- 从没有采集到的声音中恢复内容，或绕过硬件禁用、系统静音和麦克风权限。
- 保证多人抢话时逐句准确分人，或生成每个人完全干净的独立音轨。
- 自动替用户加入会议、解除 Teams 静音或改变会议音频路由。
- 当前阶段的视频剪辑、连续高帧率视频及手绘区域跟踪。

## Open questions

- 实际会议样本中，房间音响、电脑回环及麦克风分别采到什么，是否重复收录同一句远端声音？blocks: 混合场景的音轨选择与重复发言处理验收。用户安排专门会议提供验证条件。
- Teams 以 No audio 加入时，选定麦克风是否仍能被本地程序读取？blocks: 该入会方式的兼容性承诺。会外麦克风试录不能替代会内验证。
- 用户对错分说话人、漏转录和处理等待时间的可接受程度如何？blocks: 最终质量与性能验收标准；不预先承诺准确率或处理速度。

## 验收观察点

| 场景 | 可观察的目标行为 |
| --- | --- |
| 单麦克风、多人轮流发言 | 发言有时间位置；同一人再次发言仍使用同一 ID，能够人工对照录音检查 |
| 现场与远端混合 | 区分不同现场和远端说话人，不把所有扬声器声音归成一个人 |
| 当前会议统一命名 | 改一次 `Speaker 1` 的显示名，相关发言与本地衍生导出统一更新；其他说话人不变 |
| 关闭并重新打开结果 | 当前会议的名称映射仍在，另一场会议不自动继承 |
| No audio 入会 | Teams 设置保持不变；明确显示本地麦克风是否有输入，采集失败不伪报成功 |
| 虚拟线路无外放 | Teams 麦克风静音、扬声器输出到虚拟线路；本地与远端双轨可用，电脑及耳机没有实际播放声音 |
| 部分来源缺失 | 可用录音保留，状态明确指出缺失来源 |

## 规格与当前实现的差距

当前实现提供录音、会议室模式、输入检查、本地录后转录及说话人分段、会议内名称映射、片段文字校正和 Markdown/SRT 导出。原始转录保留；外部清洗通过 `transcript.edits.json` 导入，结果在界面中刷新。技术选择和运行环境见 [架构说明](architecture.md)。

公开双人语音样本与离线检查验证功能链路。2026-10-19 的 Teams 虚拟线路试录保存了 15 秒本地和远端音轨，远端可转录为英语，用户确认没有实际播放声音；Teams 双静音时未获得可用远端语音。真实混合会议的说话人质量、No audio 下的麦克风兼容性和长会议质量仍待验证。当前没有声学回声消除，不把“没有分别转录两条音轨”当作已经消除录音内回声。
