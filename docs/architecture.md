## Target structure

Windows 桌面程序保留现有 WASAPI 录音链路。浅色界面分为“录音”“录音记录”和“转录与说话人”，录音控制器继续独占设备生命周期；转录不访问录音设备，不改变 Teams 设置。

设备列表在空闲时打开下拉框、显示主窗口和开始录音前刷新。选择以名称及 loopback 类型匹配，声道数与采样率不作为身份；缺失或重名则提示重选。`Recorder.start` 在实际用于采集的同一 PyAudio 实例中重新枚举并绑定所选设备，再创建音轨和采集流，避免蓝牙连接导致旧设备编号与格式错配。设备列表不在录音或检查输入期间更新。

录音控制器同时管理可选的会议窗口截图与标记时间轴。`visuals.py` 使用 Windows Graphics Capture 绑定用户选定的 Teams 窗口句柄及进程身份；不提供桌面捕获兜底。窗口被遮挡时仍可截图，最小化或关闭时停止写入新图，音频继续。窗口与麦克风各自失败不丢弃另一部分已录数据。

截图约每 3 秒采样一次，JPEG 质量 65、保持比例缩小到 1280×720 内，不放大小图，完全重复画面不另存。`timeline.jsonl` 逐条保存图片相对路径、暂停扣除后的录音秒数、标记及状态；`review.html` 是本地生成页，复用原始音频播放并按时间查图。原始音频、原转录不迁移。

`desktop.py` 使用 pystray 驻留托盘和 Windows RegisterHotKey 注册 Alt+R / Alt+M。托盘与快捷键线程只向现有 Tk 队列派发命令；录音状态仍由控制器独占。默认隐藏主窗口，关闭主窗口只是隐藏；托盘“退出”才保存并释放设备与快捷键。托盘初始化失败时保留主窗口，快捷键冲突时明确提示并保留菜单操作。

`RecordingIndicator` 是独立的 20 像素透明工具窗口，位于主屏工作区右下角。使用 NOACTIVATE 和鼠标穿透样式，常亮表示录音，短暂颜色/空心变化反馈标记与保存；不依赖托盘图标是否被系统折叠。

`meeting.py` 在独立后台线程通过 UI Automation 确认 Teams 通话控件，再通过 Core Audio 会话确认 Teams 或其子进程正在向所选 VB-CABLE 的播放端输出。只读这些状态，不打开音频采集/播放流或修改路由。识别需要唯一会议窗口，聊天主窗口、入会预览及多窗口歧义不自动捕获。GUI 在开始录音前异步请求识别，2.5 秒内未完成则使用会议室模式；请求 token 防止取消或超时后的迟到结果启动录音。最多一个识别线程在途，识别卡住不阻碍回退录音和停止。截图目标缺失不阻断录音；已绑定窗口标题发生变化时暂停截图。

窗口捕获设置 `draw_border=False`，不修改 Teams 自身的界面。常规状态及错误使用应用内状态文字、托盘小色点和悬停详情，不发系统气泡或消息框，也不自动弹出主窗口。用户主动打开的文件选择和文字编辑窗口保留。

音频边录边写 FLAC；停止只负责停止音频、关闭文件、写会话状态并回到就绪。截图初始化、截图组件退出及回看页生成由独立后台任务负责，录音开始／停止不等待它们。原生截图退出仍设 3 秒上限，但等待属于后台任务。每个任务绑定自己的会话目录及已冻结的时钟，旧任务不能写入新录音；回看页可从已保存时间轴重新生成，采用原子替换。

转录维持独立低优先级进程，录音和转录界面不再全局互斥。只拒绝转录仍在写入的同一个会话；允许录制新会议时转录已保存的旧会议。录音完成不会切走正在处理的结果页，退出时先保存音频，取消转录不作为录音停止的前置条件。

无外放的远端录制使用用户单独安装的 VB-CABLE：Teams 输出到 `CABLE Input`，录音器通过普通 WASAPI 输入读取 `CABLE Output`，同时读取实际麦克风。系统来源枚举优先提供该接收端，并隐藏同一驱动的重复回环端点；本机安装后回环端点曾报 Invalid device，直接输入已通过实际会议试录。录音器不创建播放或监听流，Teams 麦克风静音与物理输出静音由用户保持，程序不自动改变系统路由。

录后处理由单独的本地 Python 子进程运行。GUI 只传入用户选定的音频路径、输出路径及可选人数，接收进度与结构化结果。取消或模型失败不会覆盖原音频或已有转录。独立运行环境放在便携程序旁的 `.runtime`，模型在 `models`，录音 GUI 启动不加载模型。

每个会话仍以文件夹为边界：

- `recording.json` 保存备注、文字场景与可选主要说话人 ID，独立于录音器维护的 `session.json`。列表扫描录音根的直接子目录，以目录内的开始时间显示日期。备注和选择原子写入。
- `transcription.status.json` 是安装结果时生成的轻量状态，列表无需加载完整转录；无语音警告与文件保存状态分开。

- 原录音、`session.json` 和 `HANDOFF.md` 保持现有含义。
- `transcript.raw.json` / `transcript.raw.md` 保存一次识别的不可变结果，片段含稳定 ID、时间、speaker ID 和原文。
- `speakers.json` 是本次会议的显示名映射；另一会议不继承。
- `transcript.edits.json` 保存人工或外部工具清洗后的片段文字，按片段 ID 对应。它不改变 speaker ID 或时间。
- `exports/` 存放可重新生成的 Markdown、SRT 及有清洗结果时的清洗稿。名称修改从稳定 ID 重新生成全部本地导出，不在正文中搜索替换人名。

`transcript_store.py` 负责校验结果、名称与清洗文本、落盘和导出；GUI 与外部工具共享文件契约。`transcribe_worker.py` 只负责模型推理和时间对齐；不依赖 Tk 或录音设备。

`gui/recordings.py` 提供日期列表、备注、场景和主要说话人选择。Desk 视图和正文导出复用 `focused_result`；自动建议按发言时长平方根乘语音 RMS 幅度排序，取前两个已知 ID，可显式覆盖。未知和重叠仍在正文保留。完整稿及背景/待核对稿独立导出，切回会议恢复全部。单麦克风重叠声音未进行声源分离，不能保证背景聊天完全消失。

自动分人少于 50 个有效声纹样本时，采用余弦距离 0.3 的平均链接聚类，避免短录音的十近邻图吞并次要说话人；长录音仍使用谱聚类。人数显式指定时保持原来的指定人数路径。该短录音阈值仅有当前 Desk 样本与回归样本的证据，需更多真实样本校准。

## Approach

`agent_cli.py` 提供无 GUI 的本地 JSON 接口，`WaveGrab-Agent.cmd` 使用便携目录现有 Python 运行环境启动。录音根目录取现有配置，录音 ID 限定为根目录下的一场会话。查询复用转录存储模块；AGY 整理复用 `cleanup.clean`；外部 agent 的总结经既有校验和会话锁写入，再通过原导出链路生成界面可见结果。没有新的常驻服务或数据存储。公共命令契约见 [agent-api.md](agent-api.md)。

文字清洗由独立 `cleanup.py` 进程负责，GUI 在成功安装转录后启动，录音记录页也可重试。每场用 OS 文件锁避免重复任务，锁随进程释放；状态文件和日志供界面读取。用户选择复用本机 AGY CLI 登录，无头模式通过 stdin 传入材料，默认权限、不自动批准工具，不改 AGY 登录或全局设置。

总结逐批生成最多三个术语查询，再由本地知识库脚本以 `current-work / exact_fts / company_sensitive_allowed` 检索，完整保留来源、权威等级及警告。AGY 每次收到已配置 transcript-processing 与 humanizer 的完整技能指令；transcript-processing 主导 notes 模式，保留讨论逻辑、澄清、理由和明确行动，humanizer 只润色行文。短录音直接生成总结；长会议分批整理后，再合并为一篇。结果保存在 `meeting.summary.json`，正文和核对说明分别导出到 `exports/summary.md`、`exports/summary-notes.md`。人工校正优先作为输入，原始转录及已有逐段校对保持不变。总结中的说话人采用稳定 ID 占位符，导出时应用当前显示名。结构校验拒绝空正文、无效来源片段及无效说话人；事实与信息覆盖仍须核对。

本机路径和已登录的 CLI 模型在便携程序旁 `cleanup-config.json` 配置，独立于录音配置；不纳入 Git。打包附带清洗脚本和共享转录存储模块。无原数据迁移；禁用清洗不影响本地录音和转录。

选用 faster-whisper 的本地 CPU int8 转录。说话人链路由 `speaker_diarization.py` 实现：ONNX Runtime 执行 pyannote segmentation，10 秒窗口、5 秒步长；sherpa-onnx 提取 WeSpeaker ResNet34-LM 的 VoxCeleb 声纹；SciPy 执行 WeSpeaker 的近邻图谱聚类，以特征值间隙估计人数，或采用用户填写的已知人数。自动模式搜索 1–20 组，不把本次用户估计的 5 人写死为通用人数。

至少 1.5 秒的非重叠语音参与建立声纹组，至少 0.5 秒的语音可尝试归类；与声纹中心距离过大或两个候选过近时标为未知。重叠窗口投票还原时间段，不把每个短声纹直接当作新人。少量发言者仍可能遗漏，未知标记不是完整人数统计。新版取代原来的中文 CAMPPlus 声纹与 complete-linkage 固定阈值聚类；后者在用户实际会议中过度分裂。仅新增 SciPy，保持 CPU 本地推理，无 Torch/WhisperX 运行时。新版声纹使用独立缓存文件名，保留旧缓存。

语音按词时间戳与说话人时间段匹配，遇到明确重叠标为 overlap，无匹配标为 unknown。人数默认自动，用户可指定人数帮助聚类。实际混合会议的误分率仍由用户样本验收，不把声道当作人物身份。

每次只转录一份用户选定音频，默认选择合成录音，不分别转录两路后重复拼接。房间回声在同一音频内造成的重复内容仍需实际样本验证；当前不声称有声学回声消除。

模型结果首次写入使用排他创建；已有结果不会被“再次转录”覆盖。新结果另外保留 ASR 词时间戳，后续比较说话人算法可以复用文字。旧结果缺少词时间戳时，候选重新标记只使用原片段边界，并注明这一限制；候选保存在独立子目录，不迁移原名称映射。名称映射与清洗数据写入采用同目录临时文件替换。导出失败保留权威 JSON，UI 明确提示可刷新导出；导出目录是生成内容，外部清洗通过 edits 文件提交。

## Route

1. 本地推理、结构化说话人结果及会话内名称映射；验证真实公开多人样本及改名导出一致性。
2. 两页签浅色界面，录音结束可直接进入处理，支持打开已有录音文件夹、取消处理和导出。
3. 用户的现场/远端混合会议验证；按真实录音调整质量，确认 No audio 下的设备可用性。
4. Teams 窗口截图、时间标记、离线回看及托盘快捷键；验证窗口边界、最小化/暂停行为与录音生命周期。

现有录音文件无迁移要求；新增结果独立保存，旧版仍可读取原音频和交接文件。

## Open decisions

- 专门会议样本中的回声、漏词和错分是否达到用户可接受程度；阻塞质量验收。
- 当前默认 CPU 小型多语模型的速度与准确度是否足够；阻塞长会议性能承诺，不阻塞当前本地处理入口。
